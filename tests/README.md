# Tests

These tests were "vibe coded" with AI assistance and have received little to no expert review.

Take them with a grain of salt regarding coverage, effectiveness, edge-case handling, and overall test design. They are better than nothing, but should not be considered a reliable quality gate.

Contributions and improvements are welcome.

## Layout

| Path | Needs | What it covers |
|---|---|---|
| `test_table_utils.py` | — | Markdown table rendering, HTML → MD table conversion |
| `test_libreoffice.py` | LibreOffice for 2 tests | UNO pipe naming / socket resolution / dead-pipe sweep, document → PDF, and the per-sheet page counts the spreadsheet table of contents relies on |
| `spreadsheet/test_excel2txt.py` | — | Cell-error handling, empty stripping, sheet rendering |
| `spreadsheet/test_spreadsheet_doc.py` | — | Header + table-of-contents assembly, OCR page grouping, per-section size budget |
| `spreadsheet/test_process_document_modes.py` | imports `main` (PaddleOCR) | The `auto` / `pandas` / `ocr` / `both` decision table in `_process_document` |
| `external/test_external.py` | — | External processor client (httpx MockTransport) |
| `live/` | **a running server** | Real end-to-end: see below |

Everything but `live/` runs offline with `uv run pytest tests/`.

## Live tests

`tests/live/` talks to an actual foil-serve instance and is **skipped automatically**
when none answers. It covers what the offline suite structurally cannot — chiefly
that the sheet → page map LibreOffice reports lines up with the pages PaddleOCR
returns, so the table of contents points at the right lines in real output.

Requires a GPU, the vLLM serving PaddleOCR-VL, and LibreOffice:

```bash
cd src/foil_serve && uv run uvicorn main:app --port 8081   # in another shell
uv run pytest tests/live/ -v
```

Override the target with `FOIL_SERVE_URL` (default `http://127.0.0.1:8081`) and
`FOIL_SERVE_API_KEY` (defaults to the first key in `server_config.toml`).

## Fixtures

`spreadsheet/fixtures/` is generated by `spreadsheet/generate_test_files.py`.
Two fixtures are deliberately large (~0.5–0.7 MB): `sparse_image_only.xlsx` and
`big_dense.xlsx` must exceed `excel_min_input_for_fallback_mb`, or the sparse
spreadsheet check they exist to exercise is skipped outright. Do not send
`big_dense.xlsx` through the OCR pipeline — it renders to hundreds of PDF pages.
